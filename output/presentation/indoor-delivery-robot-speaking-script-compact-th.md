# สคริปต์นำเสนอฉบับย่อ: ระบบหุ่นยนต์เคลื่อนที่อัตโนมัติสำหรับรับส่งสิ่งของภายในอาคารผ่านเว็บ

ฉบับนี้ลดเนื้อหาจากสคริปต์เต็มประมาณ 35% เหมาะสำหรับนำเสนอราว 7–8 นาทีเมื่อพูดด้วยความเร็วปกติ

## หน้า 1 — หน้าปก

สวัสดีครับ วันนี้ผมจะนำเสนอโครงงานเตรียมสหกิจศึกษา เรื่องระบบหุ่นยนต์เคลื่อนที่อัตโนมัติสำหรับรับส่งสิ่งของภายในอาคารผ่านเว็บ เป็นระบบต้นแบบที่เชื่อมการควบคุมหุ่นยนต์ ระบบนำทาง และเว็บแอปพลิเคชันเข้าด้วยกัน

เนื้อหาจะเริ่มจากปัญหาและขอบเขตของต้นแบบ ต่อด้วยโครงสร้างระบบ ผลการทดสอบ และแนวทางนำความรู้ไปใช้ในสหกิจศึกษา

## หน้า 2 — ที่มาและความสำคัญ

งานรับส่งภายในอาคารเป็นงานที่เกิดซ้ำ และผู้ใช้งานต้องติดตามว่าแต่ละงานอยู่ในขั้นใด การสั่งหุ่นยนต์ผ่านเครื่องมือ ROS 2 โดยตรงก็ไม่เหมาะกับผู้ใช้ทั่วไป

โครงงานจึงพัฒนาระบบที่ให้ผู้ใช้สร้างภารกิจ เลือกจุดรับและปลายทางจากเว็บ แล้วติดตามสถานะและประวัติของงานได้จากหน้าเดียว

แนวคิดนี้ทำให้ผู้ใช้มองเห็นขั้นตอนของภารกิจได้ชัดเจน แทนที่จะเห็นเพียงคำสั่งเคลื่อนที่ของหุ่นยนต์

## หน้า 3 — แนวคิดการทำงานของต้นแบบ

หนึ่งภารกิจเริ่มจากผู้ใช้เลือกสถานี เว็บสร้างและส่งภารกิจผ่าน Robot Agent จากนั้น Nav2 นำหุ่นยนต์ไปยังเป้าหมาย และสถานะจะส่งกลับมาอัปเดตบนเว็บ

จุดที่ต้องการพิสูจน์จึงเป็นการทำงานร่วมกันของผู้ใช้ เว็บ ระบบนำทาง และหุ่นยนต์ ไม่ใช่เพียงการสั่งให้หุ่นยนต์ไปยังพิกัดเดียว

## หน้า 4 — วัตถุประสงค์

วัตถุประสงค์คือพัฒนาฐานหุ่นยนต์ Differential Drive พัฒนาการสร้างแผนที่ ระบุตำแหน่ง และนำทางด้วย ROS 2 พัฒนาเว็บสำหรับจัดการภารกิจ และพัฒนา Robot Agent เพื่อเชื่อมเว็บกับหุ่นยนต์

สุดท้ายคือทดสอบการทำงานร่วมกันของระบบกับหุ่นยนต์จริงในพื้นที่ทดลอง

วัตถุประสงค์เหล่านี้ครอบคลุมทั้งฝั่งซอฟต์แวร์และฝั่งหุ่นยนต์ โดยประเมินตามขอบเขตของต้นแบบ

## หน้า 5 — ขอบเขตของโครงงาน

โครงงานใช้หุ่นยนต์จริง 1 คันในพื้นที่ภายในห้อง รองรับการสร้างแผนที่ ระบุตำแหน่ง นำทาง และจัดการภารกิจผ่านเว็บ

การวางและรับสิ่งของยังยืนยันผ่านเว็บ เพราะต้นแบบยังไม่มีโครงสร้างบรรทุกเฉพาะหรือเซนเซอร์ตรวจสิ่งของ จึงยังไม่ประเมินน้ำหนักบรรทุก ความปลอดภัย หรือความเสถียรระยะยาว

ดังนั้น ผลการทดสอบในส่วนถัดไปจะยืนยันเฉพาะฟังก์ชันและกรณีที่มีหลักฐานบันทึกไว้

## หน้า 6 — สถาปัตยกรรมระบบ

ระบบแบ่งเป็น Web System, Robot Agent บน ODROID-C4 และ Robot Hardware

ผู้ใช้สร้างภารกิจผ่านเว็บ ข้อมูลไปยัง Backend เพื่อบันทึกลง PostgreSQL แล้วส่งต่อ Robot Agent ผ่าน WebSocket

Agent เรียก ROS 2 และ Nav2 ให้หุ่นยนต์นำทาง Base Driver แปลงคำสั่งความเร็วส่งไปยัง ESP32 ผ่าน UART ส่วน ESP32 ควบคุมมอเตอร์และอ่าน Encoder กับ IMU

ข้อมูลตำแหน่ง สถานะนำทาง และเหตุการณ์จะส่งย้อนกลับผ่าน Agent เพื่ออัปเดตบนเว็บ ดังนั้นเว็บไม่ต้องเชื่อมต่อกับ ROS 2 หรือฮาร์ดแวร์โดยตรง

การแบ่งบทบาทแบบนี้ช่วยให้เว็บดูแลประสบการณ์ผู้ใช้ ส่วน Agent ดูแลการแปลภารกิจให้ทำงานกับระบบหุ่นยนต์ได้

## หน้า 7 — ฐานหุ่นยนต์และ Differential Drive

ฐานหุ่นยนต์ใช้ Differential Drive โดยควบคุมทิศทางจากความเร็วล้อซ้ายและขวา ODROID-C4 ประมวลผล ROS 2 ส่วน ESP32 ควบคุมมอเตอร์และอ่าน Encoder

LiDAR ใช้สแกนพื้นที่ IMU สนับสนุนข้อมูลการเคลื่อนที่ และกล้องส่งภาพสดให้ตรวจสอบผ่านเว็บ

## หน้า 8 — ฐานหุ่นยนต์ต้นแบบจริง

หน้านี้แสดงฐานหุ่นยนต์จริงที่ใช้ทดสอบ ซึ่งติดตั้งชุดล้อ มอเตอร์ คอมพิวเตอร์ และเซนเซอร์

ต้นแบบนี้ใช้พิสูจน์การสร้างแผนที่ การระบุตำแหน่ง และการนำทางบนอุปกรณ์จริง แต่ยังไม่ใช่หุ่นยนต์บรรทุกสิ่งของสมบูรณ์

เมื่อใส่รูปจริงในสไลด์ จะช่วยให้เห็นว่าอุปกรณ์ที่อธิบายในหน้าก่อนหน้าติดตั้งอยู่บนฐานเดียวกันจริง

## หน้า 9 — Mapping, Localization and Navigation

ขั้นแรก หุ่นยนต์ใช้ LiDAR และ Wheel Odometry ส่งข้อมูลให้ SLAM Toolbox สร้าง occupancy map แล้วบันทึกเป็นแผนที่สำหรับใช้งานต่อ

เมื่อเริ่มภารกิจ ระบบโหลดแผนที่ และ AMCL ใช้ LiDAR กับ Odometry เพื่อระบุตำแหน่ง ผู้ดูแลกำหนด Initial Pose ก่อน Nav2 รับเป้าหมายและวางแผนเส้นทาง

Nav2 ส่ง cmd_vel ไปยัง Base Driver และ ESP32 ควบคุมมอเตอร์ ขณะที่ Encoder ส่งข้อมูลย้อนกลับเข้าสู่ระบบ

เส้น Planned Path เป็นเส้นทางที่ระบบวางแผน ไม่ใช่เส้นทางจริงทั้งหมด และผลสำเร็จของ Nav2 หมายถึงหุ่นยนต์เข้าเงื่อนไขเป้าหมายที่ตั้งไว้

การแยก Mapping ออกจาก Localization ช่วยให้เราสร้างแผนที่หนึ่งครั้ง แล้วนำแผนที่เดิมกลับมาใช้กับภารกิจครั้งต่อไปได้

## หน้า 10 — เว็บแอปพลิเคชันและ Robot Agent

เว็บให้ผู้ใช้เลือกสถานี สร้างภารกิจ ติดตามคิว สถานะ ตำแหน่ง และประวัติ Backend ตรวจสอบและบันทึกข้อมูลก่อนส่ง Mission Command ให้ Robot Agent

Agent รับภารกิจ เรียก Nav2 action และติดตามผล จากนั้นส่ง Mission State และ Event กลับไปยังเว็บ ผู้ใช้จึงติดตามงานด้วยสถานะที่เข้าใจง่าย โดยไม่ต้องรู้รายละเอียด ROS 2

หากการนำทางผิดพลาด Agent จะส่งผลกลับเพื่อให้ Backend บันทึกสถานะเดียวกัน และแสดงให้ผู้ใช้ตรวจสอบได้

## หน้า 11 — ลำดับการทำงานของภารกิจ

ภารกิจเริ่มที่ Queued จากนั้นหุ่นยนต์ไปยังจุดรับ หรือ Going to Pickup เมื่อถึงแล้วจะรอผู้ใช้ยืนยันการวางในสถานะ Waiting for Loading

หลังยืนยัน ระบบเปลี่ยนเป็น Delivering และหุ่นยนต์ไปยังปลายทาง เมื่อถึงแล้วรอการยืนยันรับ ก่อนปิดเป็น Completed

หากผู้ใช้ยกเลิกก่อนเริ่มงานจะเป็น Cancelled และหากระบบนำทางไม่สำเร็จจะเป็น Failed ทุกการเปลี่ยนสถานะถูกบันทึกใน Event History

สถานะรอการยืนยันรับและส่งช่วยแยกขั้นตอนการเดินทางของหุ่นยนต์ออกจากขั้นตอนที่ผู้ใช้ต้องเข้ามาดำเนินการ

## หน้า 12 — การทดสอบแบ่งเป็น 3 ส่วน

เราแบ่งการทดสอบเป็น Web Application Test สำหรับสิทธิ์ ภารกิจ และประวัติ Robot Test สำหรับ SLAM และ Localization และ Integration Test สำหรับการส่งงานจากเว็บไปยังหุ่นยนต์และการส่งสถานะกลับ

การแบ่งเช่นนี้ทำให้ตรวจได้ว่าปัญหาที่พบเกิดจากส่วนเว็บ ตัวหุ่นยนต์ หรือการเชื่อมต่อระหว่างสองส่วน

## หน้า 13 — Web Application Test: สิทธิ์และหน้าจอผู้ใช้

เราทดสอบการเข้าสู่ระบบด้วยบทบาทต่างกัน ผู้ดูแลสามารถดูข้อมูลส่วนกลางและสถานะระบบ ขณะที่ผู้ใช้ทั่วไปติดตามภารกิจของตนเอง การทดสอบนี้ยืนยันว่าหน้าจอและข้อมูลแยกตามสิทธิ์ผู้ใช้

## หน้า 14 — Web Application Test: คิว สถานะ และประวัติ

ภาพด้านซ้ายแสดงรายการภารกิจพร้อมคิว เส้นทาง และสถานะล่าสุด ส่วนภาพด้านขวาเป็น Event History ของ TASK-288 ที่บันทึกเวลาและแหล่งที่มาของการเปลี่ยนสถานะ

จึงช่วยให้ผู้ใช้ติดตามงาน และช่วยให้ผู้พัฒนาตรวจสอบได้ว่าเมื่อเกิดปัญหา ระบบหยุดอยู่ที่ขั้นใด

สำหรับโครงงานนี้ Event History จึงเป็นหลักฐานของลำดับการดำเนินงาน ไม่ใช่เพียงข้อความแจ้งเตือนบนหน้าจอ

## หน้า 15 — Robot Test: SLAM and Localization

เราใช้หน้า Web Mapping รับ occupancy map จาก ROS 2 ระหว่างสำรวจพื้นที่ แล้วบันทึกเป็น Map-Test-01

จากนั้นเลือกแผนที่ กำหนด Initial Pose และตรวจว่า AMCL รายงานสถานะ Localized ซึ่งแสดงว่าระบบพร้อมสำหรับการนำทาง

## หน้า 16 — Integration Test: TASK-288 จากสถานี C ไปสถานี D

TASK-288 เริ่มจากสร้างภารกิจบนเว็บ หุ่นยนต์ไปยังสถานี C ผู้ใช้ยืนยันการวางสิ่งของจำลอง หุ่นยนต์ไปยังสถานี D แล้วผู้ใช้ยืนยันการรับ

Event Timeline แสดงเหตุการณ์ครบตั้งแต่สร้างงานจน Completed ใช้เวลารวม 2 นาที 53 วินาที ผลนี้ยืนยันการทำงานของกรณีทดสอบดังกล่าว ไม่ใช่อัตราความสำเร็จรวม

การยืนยันรับและส่งในกรณีนี้ทำผ่านเว็บตามขอบเขตของต้นแบบ ซึ่งสอดคล้องกับข้อจำกัดที่กล่าวไว้ก่อนหน้า

## หน้า 17 — สรุปผลการดำเนินโครงงาน

โครงงานพัฒนาฐานหุ่นยนต์ ROS 2 ระบบนำทาง เว็บแอปพลิเคชัน ฐานข้อมูล และ Robot Agent ให้ทำงานร่วมกันได้

ผลทดสอบแสดงการสร้างภารกิจ การติดตามสถานะ การสร้างแผนที่ การกำหนด Initial Pose และลำดับเหตุการณ์ของ TASK-288

ข้อจำกัดคือยังไม่มีโครงสร้างบรรทุกสิ่งของ และต้องทดสอบซ้ำหลายเส้นทางก่อนสรุปความเสถียรระยะยาว

จึงสรุปได้ว่าต้นแบบบรรลุเป้าหมายด้านการเชื่อมระบบและการติดตามภารกิจ แต่ยังมีงานต่อยอดด้านการขนส่งจริง

## หน้า 18 — แนวทางการดำเนินโครงงานในสถานประกอบการ

โครงงานนี้ทำให้ผมได้ฝึกการเชื่อมต่อฮาร์ดแวร์ ระบบสมองกลฝังตัว ROS 2 เว็บแอปพลิเคชัน และฐานข้อมูล

สำหรับสหกิจศึกษา ผมได้รับการตอบรับในตำแหน่ง Programmer ที่ APITechSmart Lab โดยหัวข้อโครงงานจริงจะกำหนดร่วมกับพนักงานที่ปรึกษา

ประสบการณ์จากโครงงานนี้จะเป็นพื้นฐานสำหรับงานด้านซอฟต์แวร์ ระบบสมองกลฝังตัว และ Internet of Things ต่อไป ขอบคุณครับ
